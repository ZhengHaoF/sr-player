# SR Player 网盘在线播放评估与方案

> 2026-11-12 评估收敛。范围：接入百度网盘，在线流式播放视频。
> 结论先行：**可行，走"开放平台 REST API + 现有 mpv 播放器"路线**；aPaas SDK 路线被否。

---

## 一、已确认决策（评估共识）

| # | 决策项 | 结论 | 备注 |
|---|--------|------|------|
| 1 | 产品定位 | 自己用，不刻意公开分发 | appid 已注册且**已通过上线审核**（用户数不限） |
| 2 | 提供商 | 百度网盘先行 + 通用 `VideoSource` 抽象 | 以后 WebDAV/Alist/直链只写 provider |
| 3 | 入口 UI | 新增第四个底部 Tab「网盘」 | 与文件页浏览形态保持一致 |
| 4 | MVP 范围 | 登录 + 浏览 + 流式播放 + 续播 + 清晰度切换 | 下载/搜索/字幕列为二期 |
| 5 | 技术路线 | REST API（xpan）+ media_kit(mpv) 播放 | 纯 Dart，零原生代码，零体积增量 |
| 6 | OAuth | 设备码模式 | 任意浏览器输码授权，token 30 天 + refresh_token 续期 |
| 7 | 播放源 | m3u8 转码流为主 + dlink 原画兜底 | 转码不可用自动降级原画并提示 |
| 8 | 交付物 | 本文档 | 开发另行排期 |

## 二、路线对比（为什么否掉 aPaas SDK）

### 路线 A：开放平台 REST API + mpv（采纳）

官方文档均已核实：

- 文件列表：`GET /rest/2.0/xpan/file?method=list`，`dir` 绝对路径、`limit` ≤1000、返回 `fs_id/path/server_filename/size/category`(1=视频)/`server_mtime`（[文档](https://pan.baidu.com/union/doc/基础网盘服务/获取文件信息/获取文件列表/)）
- 视频流：`GET /rest/2.0/xpan/multimedia?method=streaming&path=<URL编码云盘路径>&type=M3U8_AUTO_480/720/1080`，返回云端转码的 m3u8(HLS mpegts)（[视频播放 FAQ](https://pan.baidu.com/union/doc/faq/视频播放/)）。**实测注意：参数用 `path`，`fs_id` 会返回 errno 2 "path error"**；UA 按规范填 appName/appVersion/sysName/sysVersion
- 下载直链：`filemetas`（`dlink=1`）取 dlink，**8h 过期**、支持 Range 断点（[下载文档](https://pan.baidu.com/union/doc/基础网盘服务/下载)）；文档要求 `User-Agent: pan.baidu.com`，实测非规范 UA 也放行（校验宽松），但仍按文档设置 UA
- 容量：`GET https://pan.baidu.com/api/quota?checkfree=1&checkunfree=1`（注意：`xpan/api?method=quota` 已 404，用这个 web 风格端点）

### 探针实测（2026-11-12，token scope: basic netdisk，账号"zfy的zhf"）

| 探针 | 结果 |
|------|------|
| `xpan/nas?method=uinfo` | ✅ 200，用户信息正常 |
| `pan.baidu.com/api/quota` | ✅ 200，剩余 2.2TB（`xpan/api?method=quota` 404 已弃用） |
| `xpan/file?method=list`（全盘逐层） | ✅ errno 0，非 /apps/ 目录（如 `/电影/`）可列 |
| `xpan/file?method=listall`（递归） | ❌ 31064 "file is not authorized"——递归列表接口需额外权限，**MVP 逐层浏览不受影响** |
| `xpan/file?method=categorylist` | ❌ 31296 internal error——疑似特殊接口，MVP 不依赖 |
| `xpan/file?method=filemetas`（dlink+thumb+extra） | ✅ 返回 `info[]`（不是 `list[]`）：dlink、**视频缩略图 `thumbs.icon` ✓**、width=3840、sample_rate 等媒体信息 |
| `xpan/multimedia?method=streaming&path=...&type=480/720/1080` | ✅ 三档全部返回 m3u8（Content-Type `audio/x-mpegurl`），分片在 baidupcs.com CDN |
| **1080p 是否需会员** | ✅ **不需要**，实测返回 HEVC 1920x816 |
| 冷门格式（rmvb 1.4GB） | ✅ 也有转码 m3u8；dlink 原画兜底同样可用 |
| ffmpeg(lavf) 实播验证 | ✅ 480p H.264 960x408@24fps 与 1080p HEVC 1920x816 均稳定解码 8s，本地速度 15~65× 实时 |
| dlink 拉流 | ✅ Range 请求 206 + 数据正常 |

**mpv 接入要点（实测得出）**：百度 m3u8 的分片 URL **没有文件扩展名**，ffmpeg 7+/mpv 的 HLS 民兵检查会拒绝（`allowed_segment_extensions`），需在播放器上设置 mpv 属性 `demuxer-lavf-o=extension_picky=0`（ffmpeg 9 布尔语义；老版本等价 `allowed_extensions=ALL`）。media_kit 的 `NativePlayer.setProperty` 可直接设置。
- 授权：[设备码模式](https://pan.baidu.com/union/doc/使用入门/接入授权/设备码模式授权)，token 30 天，refresh_token 续期；未审核应用限 `/apps/{应用名}/` + 10 用户 + 10 次/小时（[权限与配额](https://pan.baidu.com/union/doc/使用入门/权限与配额/)）——**本应用已过审核，此限不适用**

mpv 直接吃 m3u8 与 dlink（mpv 原生支持 HLS、自定义 UA/header、Range）→ **Anime4K、自绘控制层、续播、倍速、方向锁定全链路原样保留**，清晰度切换 = 换 m3u8 URL 重开 + seek 回原位置。

### 路线 B：aPaas SDK（`docs/百度网盘Android_开放平台_2.10.2`，否决）

对 Demo 的逆向核实结论：

1. **播放 URL 被 SDK 封死**：内部拼 `rest/2.0/streaming` m3u8（`OwnerMediaInfo.toStreamingUrl`），应用层拿不到、也不能传 URL 给播放器 → media_kit 完全用不上。
2. 播放内核是百度自研原生 View（`ApaasMediaPlayer extends FrameLayout` 包 `com.baidu.vast.VastView`，`videosdk-oauth-2.0.2.83.aar` + `libvastcore.so`），Flutter 集成必须 PlatformView + 双向桥接 → **在线播放丢 Anime4K**。
3. 6 AAR + videosdk ≈ 58MB；.so 仅 arm64/armeabi/v7a（模拟器不可用）；Transmit/Base 合入多进程 Service/Provider（:mirroring1/:mirroring2）。
4. 工具链代差：demo AGP 4.0.1 / Kotlin 1.3.72 / compileSdk 30 / targetSdk 28；本工程 AGP 9 / Kotlin 2.3 / compileSdk 37。
5. aPaas 是另一套 appid 体系（企业合作 + 测试用户白名单，`Account` 五字段），与 union 开放平台 AppKey **不通用**。

## 三、现状事实（本项目侧）

- 播放：media_kit(libmpv)，每页独占 Player，`open(Media(path))` 只吃本地绝对路径；shader 为本地文件挂载（`glsl-shaders`，Android 分隔符 `:`），与视频源位置无关 → 在线流照常可用（[player_page.dart](../lib/pages/player_page.dart)、[shader_service.dart](../lib/services/shader_service.dart)）。
- 缺口：全项目零网络依赖；`VideoItem` 绑死本地 path，无视频源抽象；缩略图体系绑死 MediaStore/dart:io；历史页 `File(path).existsSync()` 对在线源不适用。
- 已具备：manifest 有 `INTERNET`；Riverpod + IndexedStack 三 Tab 结构，加第四 Tab 成本低。

## 四、方案概要

### 4.1 VideoSource 抽象（lib/services/ 下新增）

```dart
abstract class VideoSource {
  Future<bool> get isLoggedIn;
  Future<void> login();                                  // 设备码授权流程
  Future<void> logout();
  Future<CloudDir> listDir(String dir);                  // 分页目录列表
  Future<PlayTarget> resolvePlay(CloudEntry e);          // → 可播放 URI+headers
  Future<List<Resolution>> resolutions(CloudEntry e);    // 清晰度档位
}
```

- `PlayTarget{uri, httpHeaders, ua, resumeKey, onSwitchResolution}`；mpv 侧 `user-agent` + `http-header-fields` 注入。
- 本地视频同样收敛到 `LocalVideoSource`（uri=`file://...`，无 headers，resumeKey=path），三个入口（视频/文件/历史）逐步切过去。
- 续播 key：云端用网盘绝对路径（跨设备稳定），存键 `baidu://{path}`；续播、倍速、Anime4K 档位沿用 AppStore 现有机制。

### 4.2 播放流程

1. 点开云视频 → `resolvePlay` 取 m3u8（默认 480 起播，或记住上次档位）。
2. mpv open(streaming URL, UA) → 播放。
3. 清晰度菜单 480/720/1080/**原画(dlink)**：记录当前 position → open 新 URL → seek。streaming 接口按 type 返回单码率 m3u8，无 master playlist，换 URL+seek 是唯一可行实现（成本低，体验可接受）。
4. m3u8 失败（转码不支持/无权限/406）→ 自动降级 dlink 原画 + toast 提示原因。
5. dlink 8h 过期、401/1045（token 失效）→ 自动 refresh 后重取重试；refresh 失败 → 引导重新设备码授权。

### 4.3 网盘 Tab

- 未登录：设备码授权引导页（显示 user_code + 跳转系统浏览器到授权页，App 内轮询）。
- 已登录：与文件页一致的浏览形态（文件夹导航 + 面包屑 + 视频文件可点），分页加载（limit≤1000），排序 name/time/size。
- 登出与容量（quota）入口放本 Tab 顶部或「我的」。
- 封面：`filemetas` 的 `thumbs`（需实测视频文件是否返回缩略图），批量查询 ≤100 个 fsid，失败退化文件图标；注意配额节流。

### 4.4 Token 生命周期

- 存 `AppStore`（shared_preferences，自用可接受；不引 flutter_secure_storage）。
- 请求前检查过期 → refresh → 重试；401/1045 → 重新授权引导。
- 频控应对：目录列表与封面查询加节流与内存缓存。

## 六、风险与待验证项

**2026-11-13 功能已在 MuMu 模拟器（adb 5555）全链路实测通过**：登录态、云盘浏览（根目录/面包屑/返回手势/分页）、视频缩略图、容量头、480P/720P/1080P m3u8 流式播放、dlink 原画（10GB mkv）、清晰度切换位置连续（保存点 222s→372s 连续推进）、退出重进续播、播放记录 baidu:// 条目。剩余：

1. **真机验证**：模拟器是 x86 无 HEVC 硬解的最坏情况（1080P HEVC 起播缓冲慢、OpenGL 有 INVALID_OPERATION 噪音日志但不影响渲染）；arm64 真机硬解下预期显著更好，待真机过一遍。
2. **云盘字幕不可用**：API 流明确不支持主端字幕功能（文档原文）；外挂字幕二期做。
3. **dlink 限速**：原画档速度吃网盘会员限速策略，非会员看大文件会缓冲，属产品预期内。
4. **频控配额**：开发+测试全程约 80+ 次请求无一被限，列表与封面批量查询已做节流兜底。
5. **`categorylist`/`listall` 不可用**：一个 31296、一个 31064，均为权限类问题——MVP 的逐层浏览不依赖它们；"全部视频"聚合视图若将来要做，需向百度申请对应接口权限。
6. **刷新 token 链路**：代码已实现（refresh_token 换新 + 失败清凭据），未实测轮换（token 30 天有效）。
7. **设备码登录页**：UI 与轮询已实现，模拟器测试用 run-as 注入 token 跳过了交互授权；完整"输码→自动登录"流程待真实账号过一遍。

## 附录 A：接口调用手册（2026-11-12 实测，供后续开发/AI 直接照抄）

> 样例中的 token 均为已脱敏占位。可复跑脚本：[网盘探针参考/probe.py](网盘探针参考/probe.py)（token 从环境变量 `BD_TOKEN` 读取）。

### A.0 通用约定

- **Base**：`https://pan.baidu.com/rest/2.0/xpan/<模块>?method=<方法>&access_token=<token>`
- **access_token 一律放 query 参数**（不放 header）。
- **中文路径必须 URL 编码**后传（如 `/电影/Hello！树先生.mkv` → `/%E7%94%B5%E5%BD%B1/Hello%EF%BC%81%E6%A0%91%E5%85%88%E7%94%9F.mkv`），`dir`/`path` 参数同理。
- **UA 规范**：`<appName>/<appVersion>;<sysName>;<sysVersion>` 形式（FAQ 要求，实测不严格校验但建议遵守）。
- 成功响应 `errno: 0`；两种错误风格并存：`{errno, errmsg, request_id}`（xpan 系）与 `{error_code, error_msg, request_id}`（PCS 系）。
- **端点打错不会报 JSON 错误，而是返回 HTML 404 页**——代码里必须对"响应不是 JSON"做兜底（我们实测 `xpan/api?method=quota` 就是 HTML 404）。

### A.1 OAuth 设备码模式（实测通过）

```
① 取设备码
GET https://openapi.baidu.com/oauth/2.0/device/code
    ?response_type=device_code
    &client_id=<AppKey>
    &scope=basic,netdisk
→ {"device_code":"...","user_code":"gjhnkntn","verification_url":"https://openapi.baidu.com/device",
   "qrcode_url":"https://openapi.baidu.com/device/qrcode/<hash>/<user_code>","expires_in":300,"interval":5}

② 用户授权（5 分钟有效）：打开 verification_url，输入 user_code，确认。可给用户展示 qrcode_url 扫码。

③ 轮询换 token（每 interval 秒，建议 +2s）
GET https://openapi.baidu.com/oauth/2.0/token
    ?grant_type=device_token
    &client_id=<AppKey>
    &client_secret=<SecretKey>
    &code=<device_code>
→ 未授权时返回 {"error":"authorization_pending",...}（继续轮询）
→ 成功: {"expires_in":2592000,"refresh_token":"127.xxx","access_token":"126.xxx",
         "session_secret":"","session_key":"","scope":"basic netdisk"}
   （30 天有效期；scope 必须拿到 netdisk）

④ 刷新（未实测，M0 验证）
GET https://openapi.baidu.com/oauth/2.0/token
    ?grant_type=refresh_token&refresh_token=<rt>&client_id=<AppKey>&client_secret=<SecretKey>
```

存储建议：access_token + refresh_token + 过期时间戳持久化；请求前检查过期 → 先 refresh → 失败（401/1045）才重新设备码授权。

### A.2 基础接口（全部实测通过）

**用户信息**
```
GET /rest/2.0/xpan/nas?method=uinfo&access_token=...
→ {"errno":0,"baidu_id":...,"netdisk_name":"zfy的zhf","avatar_url":"https://himg.bdimg.com/..."}
```

**容量**（注意：官方文档写的 `xpan/api?method=quota` 已 404，实测用这个 web 风格端点）
```
GET https://pan.baidu.com/api/quota?checkfree=1&checkunfree=1&access_token=...
→ {"errno":0,"expire":false,"free":2206539448320,...}
```

**目录列表**（MVP 浏览主接口；全盘可用，不限 /apps/）
```
GET /rest/2.0/xpan/file?method=list
    &access_token=...&dir=<URL编码绝对路径>&web=1&limit=1000&order=name&desc=0
→ {"errno":0,"list":[{"fs_id":1036643525045874,"path":"/电影/Hello！树先生.mkv",
   "server_filename":"Hello！树先生.mkv","size":10909711187,"isdir":0,"category":1,
   "server_mtime":...,"md5":"..."}], ...}
```
- `category`：1 视频 / 2 音频 / 3 图片 / 4 文档 / 5 应用 / 6 其他 / 7 种子
- `isdir`: 0 文件 1 目录；分页用 `start`+`limit`
- **禁用项（实测）**：`method=listall`（递归）→ 31064 not authorized；`method=categorylist` → 31296 internal error

**文件元信息/下载直链/缩略图**（注意返回结构是 **`info[]` 不是 `list[]`**）
```
GET /rest/2.0/xpan/file?method=filemetas
    &access_token=...&fsids=[<fs_id>,...]&dlink=1&thumb=1&extra=1
→ {"errno":0,"info":[{"dlink":"https://d.pcs.baidu.com/file/<hash>?fid=...&sign=...&expires=8h&...",
   "thumbs":{"icon":"https://thumbnail0.baidupcs.com/thumbnail/...?...&size=c60_u60&expires=8h"},
   "width":3840,"sample_rate":48000,"scene_info":"[0,20,31,...]",...}]}
```
- fsids 是 JSON 数组字符串，≤100 个；**视频也有缩略图**（thumbs.icon 实测存在）
- **ⓘ thumbs 仅在 `dlink=1` 时返回**（thumb=1 单独请求不返回，实测踩坑）；thumbs 键有 icon/url1/url2/url3 四档（60/117/254/531px），URL 无需 UA 直接可拉，8h 签名有效期
- **dlink 8h 过期**，过期重查 filemetas（errno 31360）
- dlink 使用：`GET <dlink>&access_token=<token>` + 请求头 `User-Agent: pan.baidu.com`，支持 `Range: bytes=x-y`（实测 206）；可能 302 需跟随；文档说防盗链 31326，实测非规范 UA 也放行（校验宽松，仍按规范设置）
- `scene_info` 是场景切分点数组，可做进度条缩略图预览（二期）

### A.3 视频流式播放（核心，实测通过）

```
GET /rest/2.0/xpan/multimedia?method=streaming
    &access_token=...
    &path=<URL编码云盘绝对路径>          ← 必须用 path！fs_id 会报 errno 2 "path error"
    &type=M3U8_AUTO_480 | M3U8_AUTO_720 | M3U8_AUTO_1080
→ 直接返回 m3u8 文本（Content-Type: audio/x-mpegurl）
  #EXTM3U
  #EXT-X-TARGETDURATION:15
  #EXT-X-DISCONTINUITY
  #EXTINF:10,
  http://yqall06.baidupcs.com/video/netdisk-videotran-baoding/...（分片绝对 URL，无文件扩展名）
```

实测关键事实：
- **参数名是 `path` 不是 `fs_id`**（第三方流传的 fs_id 写法实测 errno 2）
- 480=H.264 / **1080=HEVC 1920x816 且无需会员**
- 分片在 `*.baidupcs.com` CDN，普通 http GET 即可拉（带 Range 返回 206）
- **rmvb 等冷门格式也有云端转码**（实测 1.4GB rmvb 返回 m3u8）
- 清晰度切换 = 记录 position → 用新 type 的 URL 重新 open → 回跳原位置

**ⓘ 换档/续播定位的实现教训（2026-11-13 MuMu 实测）**：HLS 流打开初期对 mpv 做
post-open `seek` 会被 demuxer 竞态丢弃（偶发直接跳到片尾），且打开初期 position
流从 0 上报，会把续播点覆盖成毫秒级毒数据。最终方案：
1. **用 mpv `start` 属性在加载期定位**——`setProperty('start', '877.000')` 后 open，
   mpv 装载 m3u8 时原生处理，无竞态；
2. 加载后轮询校验位置到位，未到位再直 seek 补偿；
3. "保存门闩"——打开/换档期间 position 低于 seek 目标时禁止写入续播点
   （10s 兜底解除）。
   实现见 `lib/pages/player_page.dart` 的 `_openMedia`。

### A.4 mpv / media_kit 接入要点（实测得出）

- **分片 URL 无扩展名**，ffmpeg 7+ 的 HLS 检查会拒绝（`allowed_segment_extensions`）。mpv 需设：
  - ffmpeg 9+：`demuxer-lavf-o=extension_picky=0`（布尔，实测 9.0.2 通过）
  - 旧版等价：`allowed_extensions=ALL`
  - media_kit 写法：`NativePlayer.setProperty('demuxer-lavf-o', 'extension_picky=0')`
- UA 设置：`Media(uri, httpHeaders: {'User-Agent': '...'})`（media_kit 原生支持），或 mpv `user-agent` 属性
- streaming/dlink 的 URL 带 access_token，**别打进日志**

### A.5 实测错误码速查

| 码 | 场景 | 处理 |
|----|------|------|
| 0 | 成功 | — |
| errno 2 "path error" | streaming 用了 fs_id 参数 / 路径不存在 | 改用 path |
| errno 2 "unsupported api" | method 名不存在 | 核对 method |
| 31064 "file is not authorized" | listall 递归接口无权限 | 用 method=list 逐层 |
| 31296 "internal error" | categorylist 无权限 | 不依赖该接口 |
| 31360 | dlink 过期 | 重新 filemetas |
| 31326 | dlink 防盗链 | UA: pan.baidu.com |
| 1045 | token 校验失败 | refresh / 重新授权 |
| 20013 | 无接口访问权限 | 检查应用接口白名单 |
| HTML 404 页 | 端点/参数拼错 | 非 JSON 兜底 |
